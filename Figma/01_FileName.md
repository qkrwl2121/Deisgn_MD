# 파일/레이어 네이밍 가이드 (Figma)

Figma 작업 시 화면(프레임) 이름, 레이어 이름, 아이콘·이미지·버튼 등 요소 이름을 통일성·효율성 있게 관리하기 위한 규칙이다. (원본: node-id `434:1493`, "01 File Name")

## 작업 프로세스 및 보고 규칙 (모든 점검·수정 공통)

이 문서 기준으로 점검·수정 작업을 진행할 때는 항상 아래 절차를 따른다.

1. **이해** — 사용자의 요청이 정확히 무엇을 대상으로 하는지(어떤 노드·프레임·범위) 파악한다.
2. **분석** — 이 문서에 정의된 규칙과 대상의 현재 상태를 비교해 어떤 항목을 확인해야 하는지 정리한다.
3. **탐색** — `get_metadata`/`use_figma` 등으로 실제 값을 전수 조사한다. 이 단계에서 겉보기 속성(예: `strokeWeight` 숫자값)만 보지 말고, 그 속성이 실제로 적용되고 있는지(예: `strokes` 배열이 비어있지 않은지)까지 확인한다 — 적용되지 않는 leftover 값을 오류로 오인하지 않도록 주의한다.
4. **계획** — 발견한 사항을 "값 자체가 규칙과 다른 경우"와 "값은 맞는데 반영/바인딩만 빠진 경우"로 구분해 정리한다.
5. **검증** — 결론을 내리기 전에 관련 레이어를 개별로 다시 확인(스크린샷·개별 노드 조회 등)해 오탐이 없는지 재확인한다.

**오류가 발견되면 어떤 경우에도 바로 수정하지 않는다.** 발견한 내용을 먼저 표/목록으로 사용자에게 보고하고, 사용자의 확인을 받은 뒤에만 수정을 진행한다. (이 문서의 다른 절에 "값만 같으면 확인 없이 바로 바인딩 가능" 같은 예외가 있더라도, 이 규칙이 우선한다.)

## 1. 화면(File) 이름 규칙 — ⚠ 초안 (미확정)

> 이 섹션은 Figma 원본에서 "정리 필요 (확인 X)"로 별도 표시되어 있다. 아직 확정된 규칙이 아니므로, 확정 전까지는 아래 4번 "오류 판정 기준"에 포함하지 않는다.

패턴:

```
구분/No메뉴명_No메뉴명_화면ID
```

예시: `공통/01회원관리_01회원가입_EV-CS-101PAG01`

| 구성 요소 | 의미 | 예시 |
|---|---|---|
| 구분 | 대분류/영역 | 공통 |
| 1depth | No + 상위 메뉴명 | 01회원관리 |
| 2depth | No + 하위 메뉴명 | 01회원가입 |
| 3depth (화면 ID) | 화면 고유 ID | EV-CS-101PAG01 |

## 2. 레이어(Layer) 이름 규칙

- 레이어명은 **첫 글자만 대문자, 이후는 소문자**로 작성한다.
- 레이어 트리의 중첩 깊이(depth)를 접두사 기호로 표시한다.

| 접두사 | 의미 | 깊이 | 예시 |
|---|---|---|---|
| `++그룹명` | 최상위 구조 그룹 (레이아웃) | 1단계 | `++Header`, `++ container`, `++footer`, `++Floating` |
| `+ 하위그룹` | 구조 그룹 하위 섹션 | 2단계 | `+ section 01`, `+ section 02`, `+ section 03` |
| `- 하위그룹` | 콘텐츠 그룹 (이 단계부터 부호가 `-` 계열로 전환) | 3단계 | `- List`, `- image`, `- 기타 등등` |
| `-- 하위그룹` | 콘텐츠 그룹 내부 개별 요소 | 4단계 | `-- Num`, `-- Btn`, `-- 기타 등등` |

- `+` 계열(`++` → `+`)은 **레이아웃/구조 단위**, `-` 계열(`-` → `--`)은 **콘텐츠/요소 단위**를 나타낸다.
- 같은 계열 안에서는 기호 수가 늘어날수록(`++`→`+`, `-`→`--`) 더 얕은/깊은 단계가 아니라, `+`는 개수가 줄고 `-`는 개수가 느는 방향으로 깊어진다 — 표의 깊이 열 그대로 따른다.

## 3. 요소 타입별 네이밍 (아이콘/이미지/버튼)

| 타입 | 규칙 | 예시 |
|---|---|---|
| 아이콘 | `icon_콘텐츠명` | `icon_notice`, `icon_menu`, `icon_home` |
| 이미지 | `img_콘텐츠명` | `img_card`, `img_phone`, `img_gift` |
| 버튼 | `btn_콘텐츠명` | `btn_check`, `btn_next`, `btn_prev` |

## 작업 순서 (Figma MCP 기준)

1. 대상 프레임의 레이어 트리를 `get_metadata`로 파악해 현재 이름·중첩 구조를 조사한다.
2. 각 레이어를 아래 기준으로 분류한다.
   - 최상위 구조 그룹 → `++그룹명`
   - 구조 그룹 하위 섹션 → `+ 하위그룹명`
   - 콘텐츠 그룹 → `- 하위그룹명`
   - 콘텐츠 그룹 내부 개별 요소 → `-- 하위그룹명`
   - 아이콘/이미지/버튼 노드 → `icon_`/`img_`/`btn_` + 콘텐츠명
3. `node.name = ...`으로 일괄 변경하고, 변경된 노드 ID를 모두 반환해 기록한다.
4. 변경 후 레이어 패널 트리를 재조회하여 깊이와 접두사가 일치하는지 검증한다.

## 4. 오류 판정 기준

- 레이어명 첫 글자가 대문자가 아니거나, 이후 글자에 불필요한 대문자가 섞여 있음
- 레이어의 실제 트리 깊이와 접두사(`++`/`+`/`-`/`--`)가 일치하지 않음
- 아이콘/이미지/버튼으로 쓰이는 레이어명이 각각 `icon_`/`img_`/`btn_` 접두사를 따르지 않음
- 화면(File) 이름 규칙은 **미확정 상태이므로 오류 판정 대상에서 제외**한다. 확정되면 이 문서에 반영 후 판정 기준에 추가한다.
