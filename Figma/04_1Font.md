# 폰트 일괄 수정 가이드 (Figma)

Figma 디자인 파일에서 폰트를 일괄 교체할 때 아래 규칙을 기준으로 삼는다. 이 값에서 벗어나면 오류로 간주한다.

## 작업 프로세스 및 보고 규칙 (모든 점검·수정 공통)

이 문서 기준으로 점검·수정 작업을 진행할 때는 항상 아래 절차를 따른다.

1. **이해** — 사용자의 요청이 정확히 무엇을 대상으로 하는지(어떤 노드·프레임·범위) 파악한다.
2. **분석** — 이 문서에 정의된 규칙과 대상의 현재 상태를 비교해 어떤 항목을 확인해야 하는지 정리한다.
3. **탐색** — `get_metadata`/`use_figma` 등으로 실제 값을 전수 조사한다. 이 단계에서 겉보기 속성(예: `strokeWeight` 숫자값)만 보지 말고, 그 속성이 실제로 적용되고 있는지(예: `strokes` 배열이 비어있지 않은지)까지 확인한다 — 적용되지 않는 leftover 값을 오류로 오인하지 않도록 주의한다.
4. **계획** — 발견한 사항을 "값 자체가 규칙과 다른 경우"와 "값은 맞는데 반영/바인딩만 빠진 경우"로 구분해 정리한다.
5. **검증** — 결론을 내리기 전에 관련 레이어를 개별로 다시 확인(스크린샷·개별 노드 조회 등)해 오탐이 없는지 재확인한다.

**오류가 발견되면 어떤 경우에도 바로 수정하지 않는다.** 발견한 내용을 먼저 표/목록으로 사용자에게 보고하고, 사용자의 확인을 받은 뒤에만 수정을 진행한다. (이 문서의 다른 절에 "값만 같으면 확인 없이 바로 바인딩 가능" 같은 예외가 있더라도, 이 규칙이 우선한다.)

## 1. 폰트 패밀리

- 모든 텍스트를 **Pretendard**로 통일한다.
- 이미 Pretendard인 텍스트는 그대로 두고, 다른 폰트(예: ThecircleB 등)만 교체한다.
- 스타일(Regular/Medium/SemiBold/Bold 등)은 기존 굵기를 최대한 유지한다. 대응하는 스타일이 없으면 가장 가까운 굵기로 대체한다.

## 2. 폰트 크기 (Font Size)

- 최종 크기는 **짝수(2의 배수)**여야 하며, **최소 12px**를 넘어야 한다(12px 미만으로 내리지 않음).
- 홀수인 경우 다음 짝수로 올림한다.
  - 예: 11 → 12, 13 → 14, 15 → 16
- 이미 짝수이고 12 이상이면 값을 변경하지 않는다.
- 규칙(의사코드):
  ```
  newSize = fontSize < 12 ? 12 : (fontSize % 2 === 0 ? fontSize : fontSize + 1)
  ```

## 3. 줄 간격 (Line Height)

- 위에서 보정한 **최종 폰트 크기 기준**으로 계산한다.
- `line height = fontSize × 1.5` 를 구한 뒤, **4pt 그리드에 맞춰 가장 가까운 4의 배수**로 반올림한다.
- 단위는 `PIXELS`로 명시 설정한다(AUTO 금지).
- 규칙(의사코드):
  ```
  target = Math.round((fontSize * 1.5) / 4) * 4
  ```
- 참고 매핑표 (자주 쓰는 크기 기준):

  | 폰트 크기 | ×1.5 | 4pt 보정 라인하이트 |
  |---|---|---|
  | 12 | 18 | 20 |
  | 14 | 21 | 20 |
  | 16 | 24 | 24 |
  | 18 | 27 | 28 |
  | 20 | 30 | 32 |
  | 24 | 36 | 36 |
  | 32 | 48 | 48 |
  | 40 | 60 | 60 |

## 4. 로고(Logo) 텍스트 예외

- 브랜드 워드마크/로고로 사용되는 텍스트(예: 헤더·푸터의 프로젝트명/로고 텍스트)는 **폰트로 취급하지 않는다.**
- 위 1~3번 크기·줄간격 보정 규칙의 적용 대상에서 제외하며, **Text Styles(로컬 텍스트 스타일)에도 등록하지 않는다.**
- 이미 Text Style이 바인딩되어 있다면 바인딩을 해제(`setTextStyleIdAsync("")`)하고, 해당 스타일이 로고 전용으로만 쓰였다면 스타일 자체도 삭제한다.
- 로고 텍스트 노드 자체의 폰트/크기/줄간격 값은 별도로 변환하지 않고 그대로 둔다(디자이너가 로고로 별도 관리).

## 작업 순서 (Figma MCP 기준)

1. `get_metadata`로 대상 프레임 구조 파악 → 대상 노드 ID 확보.
2. `use_figma`로 대상 프레임 내 모든 TEXT 노드를 순회하며 `getStyledTextSegments(["fontName","fontSize","lineHeight"])`로 현재 값 조사.
3. 위 규칙에 따라 각 노드의 목표 fontFamily / fontSize / lineHeight 계산.
4. `loadFontAsync`로 현재 폰트(및 필요 시 대상 폰트)를 로드한 뒤 `fontName` / `fontSize` / `lineHeight`를 순서대로 적용.
   - 폰트 패밀리 교체 후 크기·줄간격을 적용하는 순서 권장.
   - 원본 폰트가 시스템에 없어 로드 실패 시, 원본 폰트 로드 없이 대상 폰트(Pretendard)만 로드한 뒤 `fontName`을 덮어써도 된다.
5. 마지막에 전체 텍스트 노드를 재조회하여 다음을 검증:
   - `fontName.family === "Pretendard"`
   - `fontSize % 2 === 0 && fontSize >= 12`
   - `lineHeight.unit === "PIXELS" && lineHeight.value === Math.round(fontSize*1.5/4)*4`
   - 불일치 항목이 있으면 오류로 보고.

## 오류 판정 기준

다음 중 하나라도 해당하면 오류로 판단한다.

- 폰트 패밀리가 Pretendard가 아님
- 폰트 크기가 홀수이거나 12 미만
- 라인 하이트가 `fontSize × 1.5`의 4pt 보정값과 다름 (unit이 PIXELS가 아닌 경우 포함)
- 로고 텍스트에 Text Style이 바인딩되어 있음 (로고는 Text Styles 대상에서 제외)
