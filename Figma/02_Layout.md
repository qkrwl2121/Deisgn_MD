# 레이아웃(그리드) 가이드 문서 검토 및 등록 가이드 (Figma)

Figma 디자인 파일 내 레이아웃 가이드 문서("02 Layout" 프레임 등)를 검토하여, 그 내용을 Figma Grid Style로 등록할 때 사용하는 규칙이다.

> Division Spacing(여백·간격) 관련 규칙·Variables·적용 이력은 `05_Spacing.md`로 분리되어 있다. 이 문서는 **Grid(그리드)** 만 다룬다.

## 작업 프로세스 및 보고 규칙 (모든 점검·수정 공통)

이 문서 기준으로 점검·수정 작업을 진행할 때는 항상 아래 절차를 따른다.

1. **이해** — 사용자의 요청이 정확히 무엇을 대상으로 하는지(어떤 노드·프레임·범위) 파악한다.
2. **분석** — 이 문서에 정의된 규칙과 대상의 현재 상태를 비교해 어떤 항목을 확인해야 하는지 정리한다.
3. **탐색** — `get_metadata`/`use_figma` 등으로 실제 값을 전수 조사한다. 이 단계에서 겉보기 속성(예: `strokeWeight` 숫자값)만 보지 말고, 그 속성이 실제로 적용되고 있는지(예: `strokes` 배열이 비어있지 않은지)까지 확인한다 — 적용되지 않는 leftover 값을 오류로 오인하지 않도록 주의한다.
4. **계획** — 발견한 사항을 "값 자체가 규칙과 다른 경우"와 "값은 맞는데 반영/바인딩만 빠진 경우"로 구분해 정리한다.
5. **검증** — 결론을 내리기 전에 관련 레이어를 개별로 다시 확인(스크린샷·개별 노드 조회 등)해 오탐이 없는지 재확인한다.

**오류가 발견되면 어떤 경우에도 바로 수정하지 않는다.** 발견한 내용을 먼저 표/목록으로 사용자에게 보고하고, 사용자의 확인을 받은 뒤에만 수정을 진행한다. (이 문서의 다른 절에 "값만 같으면 확인 없이 바로 바인딩 가능" 같은 예외가 있더라도, 이 규칙이 우선한다.)

## 0. 두 가지 시나리오 — 어떤 절차를 쓸지 먼저 구분한다

이 문서는 방향이 반대인 두 절차를 모두 다룬다. 사용자 요청을 받으면 아래 기준으로 먼저 어느 쪽인지 판단하고, 애매하면 진행 전에 사용자에게 확인한다.

- **A. 가이드 → 프레임 적용**: 레이아웃 가이드 문서(그리드)가 이미 정의돼 있고, 그 값을 실제 화면(프레임)에 적용하고 싶을 때.
- **B. 프레임 → 가이드 정의** (역방향): 화면(메인 프레임)을 먼저 작업했고, 거기서 실제 쓰인 그리드를 뽑아 가이드 문서·스타일 자체를 새로 정의/교정하고 싶을 때. 예: "메인에서 쓴 그리드 뽑아서 가이드에 반영해줘"

두 절차 모두 결과물은 동일하게 Grid Style 등록 + 가이드 문서 반영 + 프레임 적용이지만, **출발점(가이드가 원본인지, 프레임이 원본인지)이 반대**라는 점이 핵심 차이다.

## 1. Grid 규칙

- 기준 해상도: 1920px
- 컨텐츠 영역: 1200px (좌우 마진 각 360px)
- 컬럼: 12 Columns (컬럼 폭 78px)
- Gutter: 24px
- Figma Grid Style 이름: `PC_12C` (`pattern: COLUMNS`, `count: 12`, `gutterSize: 24`, `offset: 360`, `alignment: STRETCH`)

## 2. 등록 절차 (Figma MCP 기준)

1. 가이드 프레임("02 Layout" 등)의 `01_Grid` 섹션을 `get_metadata`/스크린샷으로 확인해 기준 수치를 파악한다.
2. 이미 동일 이름의 Grid Style이 있는지 `getLocalGridStylesAsync()`로 먼저 확인한다. 없으면 `figma.createGridStyle()`로 생성하고 `layoutGrids`에 COLUMNS 패턴·count·gutterSize·offset·alignment를 설정한다.
3. 기존에 등록된 스타일이 있다면 실제 값을 규칙과 비교한다. 가이드 수치와 다르면 전량 삭제 후 재등록한다. 이미 규칙에 맞으면 유지한다.
4. 대상 프레임(예: "Main")에 Grid Style을 연결(`gridStyleId`)한다. raw `layoutGrids` 값만 동일하고 스타일에 연결되지 않은 상태는 미완료로 본다.
5. 등록된 스타일을 재조회해 이름·값이 의도대로 등록됐는지 검증한다.

## 3. 프레임 → 가이드 역방향 절차 (B 시나리오)

1. 대상 메인 프레임의 실제 `layoutGrids`를 전수 스캔해 분석한다.
2. 그리드가 가이드와 다르면(컬럼 수·거터·오프셋), 실제 프레임 값을 기준으로 가이드 문서의 수치 라벨과 그림(컬럼 사각형 크기·위치)을 갱신한다.
   - 가이드 안에서 설명 텍스트와 실제 그려진 도형 수치가 서로 어긋나 있는 경우가 있을 수 있다. 반드시 **라이브 노드 값을 기준**으로 삼는다 — `get_metadata`는 캐시로 인해 값이 실제 라이브 상태와 다를 수 있으므로, 수정 후에는 `use_figma` 스크립트로 라이브 값을 재확인한다.
3. 확인된 값을 Grid Style로 등록하고, 대상 프레임에 연결한다.

## 4. 오류 판정 기준

- Grid Style의 count/gutterSize/offset이 가이드 문서 수치와 다름
- 가이드 문서 안에서 설명 텍스트(예: "1200px")와 실제 그려진 그리드 수치(컬럼 폭·전체 폭)가 서로 다름
- 프레임의 그리드가 스타일에 연결(`gridStyleId`)되지 않고 동일한 값을 raw로만 갖고 있음 (스타일 미연결)
- 신규 등록 전, 삭제가 필요한 상황(규칙 위반 값 존재)인데 기존 스타일을 삭제하지 않고 중복/방치함
