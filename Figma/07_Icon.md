# 아이콘(Icon) — Keyline 가이드 (Figma)

아이콘은 사이즈별 Keyline(픽셀 그리드 기반 구성 가이드)을 토대로 제작하여 전체 아이콘에서 일관된 시각적 비율·규칙을 갖도록 한다. 아직 Icon 단계 전체 규칙이 확정된 것은 아니며(Style_Guide.md 1번 표에 "미정"으로 남아있던 단계), 이번에 "01_Size" 섹션(Keyline 크기 차트)부터 실제로 진행하며 학습한 규칙만 우선 문서화한다.

## 작업 프로세스 및 보고 규칙 (모든 점검·수정 공통)

이 문서 기준으로 점검·수정 작업을 진행할 때는 항상 아래 절차를 따른다.

1. **이해** — 사용자의 요청이 정확히 무엇을 대상으로 하는지(어떤 노드·프레임·범위) 파악한다.
2. **분석** — 이 문서에 정의된 규칙과 대상의 현재 상태를 비교해 어떤 항목을 확인해야 하는지 정리한다.
3. **탐색** — `get_metadata`/`use_figma` 등으로 실제 값을 전수 조사한다. 이 단계에서 겉보기 속성(예: `strokeWeight` 숫자값)만 보지 말고, 그 속성이 실제로 적용되고 있는지(예: `strokes` 배열이 비어있지 않은지)까지 확인한다 — 적용되지 않는 leftover 값을 오류로 오인하지 않도록 주의한다.
4. **계획** — 발견한 사항을 "값 자체가 규칙과 다른 경우"와 "값은 맞는데 반영/바인딩만 빠진 경우"로 구분해 정리한다.
5. **검증** — 결론을 내리기 전에 관련 레이어를 개별로 다시 확인(스크린샷·개별 노드 조회 등)해 오탐이 없는지 재확인한다.

**오류가 발견되면 어떤 경우에도 바로 수정하지 않는다.** 발견한 내용을 먼저 표/목록으로 사용자에게 보고하고, 사용자의 확인을 받은 뒤에만 수정을 진행한다. (이 문서의 다른 절에 "값만 같으면 확인 없이 바로 바인딩 가능" 같은 예외가 있더라도, 이 규칙이 우선한다.)

## 0. 원본(참조) 위치

- "★ Style Guide" 페이지가 아닌, **"Icon" 원본 레퍼런스 페이지**(node-id `607:2875`)에 실제 아이콘 제작 기준이 정의되어 있다.
- 그 안의 "Keyline guide" 프레임(node-id `607:2899`)이 Keyline 개념을 설명하는 원본 문서다.
  - 타이틀: "Keyline Guide" (Lato Bold 40px)
  - 스펙 텍스트 12개(그리드값 12/16/20/24/32/40/48/56/64/72/80/104 각각에 대해 `Pixel grid` / `Circle (Diameter)` / `Square` / `Rectangle (Horizontal)` / `Rectangle (Vertical)` 5줄, Pretendard Regular 8px, `paragraphSpacing: 6`, 고정폭 120 + `textAutoResize: HEIGHT`)
  - "Keyline" **COMPONENT_SET**(node-id `607:2914`) — Variant 이름 `Size=Keyline_{N}`(N = 12/16/20/24/32/40/48/56/64/72/80/104), 각 변형의 실제 렌더 크기가 이름의 숫자와 동일(`Keyline_16` = 16×16 등). 이 12개 변형이 겹쳐서 한 다이어그램으로 배치돼 있는 것이 참조 프레임의 시각 다이어그램이다(보라색 점선 테두리, `dashPattern: [10,5]`, stroke color `#9747FF` 근사).

## 1. 핵심 규칙 — 폴더(항목) 이름 = 그리드 값 = 사용하는 Variant 번호

- Keyline 크기 차트에서 각 항목(칼럼)의 **이름은 그 항목이 나타내는 그리드 값 그대로**이며, 그 항목이 쓰는 Keyline 인스턴스도 **같은 숫자의 Variant**(`Size=Keyline_{같은 숫자}`)여야 한다.
  - 예: "16" 항목 → `Size=Keyline_16`(16×16) 인스턴스, 라벨 "16x16".
  - **"Square" 스펙 값(예: 그리드 16의 Square는 12)과 혼동하지 않는다** — Square는 스펙 설명 텍스트에만 쓰이는 별도 수치이고, 실제 스와치 인스턴스 선택 기준이 아니다.
- 각 항목의 구조(하나의 VERTICAL auto-layout, `itemSpacing: 20`):
  1. Keyline 인스턴스 (해당 숫자의 Variant, `{N}×{N}` 크기)
  2. 텍스트 라벨 `"{N}x{N}"` (Pretendard Medium 18px)
  3. 스펙 텍스트 5줄(`Pixel grid: N` / `Circle (Diameter): X` / `Square: Y` / `Rectangle (Horizontal): W*H` / `Rectangle (Vertical): H*W`, Pretendard Regular 8px, `paragraphSpacing: 6`, 고정폭 120, `textAutoResize: HEIGHT`, fill 거의 검정 `rgb(0.071, 0.076, 0.102)`) — 원본 참조 문서는 이 스펙 텍스트 첫 줄에 굵은 글씨로 숫자(`N`)를 한 번 더 반복하지만, 이 프로젝트의 "01_Size" 리스트는 바로 위에 이미 `{N}x{N}` 라벨이 있으므로 중복을 피해 그 줄은 생략하고 `Pixel grid: N`부터 시작한다.
- 리스트(`List`, HORIZONTAL auto-layout)는 그리드값 오름차순(12→16→20→24→32→40→48→56→64→72→80→104)으로 배치한다.

## 2. 컨테이너 폭 재조정 필요

- "01_Size"·"contents" 프레임은 `counterAxisSizingMode: FIXED`(고정폭)이고, 최상위 "07 Icon" 프레임은 `layoutMode: NONE` + `clipsContent: true`다. 항목을 12개로 늘리면 `List`의 총 폭이 커지므로(스펙 텍스트 고정폭 120이 기존보다 넓어 각 항목 폭도 함께 늘어남), **`List`가 커진 만큼 "01_Size"·"contents"의 폭을 수동으로 늘리고, 최상위 "07 Icon" 프레임도 좌우 여백(기존과 동일하게 100px씩)을 유지하도록 폭을 재계산**해야 클리핑 없이 전부 보인다.
- 계산식: `07 Icon 프레임 폭 = 좌측 여백(100) + List 최종 폭 + 우측 여백(100)`.

## 3. "02_Line" — 라인(작화) 규칙

사용자가 "07 Icon" 프레임(node-id `861:4986`)에 직접 "02_Line" 섹션(node-id `877:8994`, 타이틀 "Line Type")을 추가해 두 가지 하위 규칙을 정의했다. 01_Size(Keyline 크기 차트)와 달리 이 섹션은 **아이콘 작화 시 지켜야 할 비율·선 두께 규칙**을 다룬다.

### 3-1. Area — 아이콘 비율(Ratio) 규칙 ("01_area", node-id `877:9001`)

- 아이콘은 80×80 Keyline(`Size=Keyline_80` 인스턴스) 안에 그리는 것을 기준 예시로 삼되, 실제 그림(Vector)이 채우는 영역은 **아이콘의 가로:세로 비율에 따라 3가지 유형**으로 나뉜다. 각 유형은 Keyline 대비 그림 영역의 여백(마진)이 다르다.

| 유형 | 라벨 | Vector 크기(80×80 Keyline 기준) | 여백(상하/좌우) |
|---|---|---|---|
| 정비율(1:1) | "정비율" | 58×58 | 상하 11px / 좌우 11px |
| 세로비율(세로가 긴 경우) | "세로비율" | 50×66 | 상하 7px / 좌우 15px |
| 가로비율(가로가 긴 경우) | "가로비율" | 67.25×53 | 상하 13.5px / 좌우 6px |

- 예시 아이콘의 벡터 `strokeWeight`는 3종 모두 **1.5**이며, 색상은 raw 값이 아니라 `Color` 컬렉션의 시맨틱 토큰 **`Font/Strong`**에 바인딩되어 있다(`03_Color.md` 11번의 시맨틱 컬러 체계를 아이콘 라인 색상에도 그대로 재사용한 사례).
- 라벨 텍스트: "Area"(섹션 제목, Pretendard SemiBold 24px), "정비율"/"세로비율"/"가로비율"(각 칩 라벨, Pretendard Medium 16px).

### 3-2. Stroke — 사이즈별 선 두께 규칙 ("02/03/04_Stroke..", node-id `877:9008`/`877:9017`/`877:9024`)

- 아이콘 사이즈에 따라 권장 선(stroke) 두께가 다르며, 3개 구간으로 나눈다.

| 사이즈 구간 | 권장 Stroke 두께 |
|---|---|
| 16, 20px | 1.2px |
| 24px | 1.5px |
| 32px 이상 | 2px |

- 각 구간은 실제 데모 아이콘(`Icon/20px` 컴포넌트, `Property 1=20, Property 2=Home` 변형 — **3개 구간 모두 같은 마스터를 재사용**, 아이콘 자체가 사이즈별로 다시 그려진 것은 아님)에 빨간색 측정 가이드선(`strokeWeight: 0.5`, 색상 `#FF0000`, raw 값)과 "1.2px"/"1.5px"/"2px" 라벨(Roboto Regular 16px)을 덧붙여 시각적으로 설명한다.
- 실제 `Icon/20px` 마스터 내부 Vector의 `strokeWeight`는 1.2로 고정되어 있음을 확인함(16·20px 구간 값과 일치) — 이는 **데모용 마스터가 16/20px 기준값(1.2px)으로 만들어져 있고, 24px·32px 구간은 값 차이를 텍스트 라벨로만 안내하는 것**이라는 뜻이다. 실제 24px·32px 아이콘을 작화할 때는 그 아이콘 자체의 벡터 strokeWeight를 표에 따라 1.5px·2px로 지정해야 한다(데모 아이콘의 고정된 1.2px를 그대로 따르면 안 됨).

## 4. 오류 판정 기준

- 항목(폴더) 이름과 실제 사용된 Keyline Variant의 숫자가 다름(라벨과 인스턴스 크기가 폴더명과 불일치)
- 리스트가 그리드값 오름차순으로 정렬되지 않음
- 스펙 텍스트의 Circle/Square/Rectangle 수치가 원본 "Keyline Guide"(607:2899) 스펙과 다름
- 컨테이너 폭 재조정을 누락해 항목이 최상위 프레임 경계 밖으로 잘림(clipping)
- 실제 아이콘 벡터가 3-1번 비율 표(정비율 58×58/세로비율 50×66/가로비율 67.25×53, 80×80 Keyline 기준)의 여백 비율과 다름
- 아이콘 라인 색상이 `Font/Strong` 시맨틱 토큰이 아니라 raw 값이거나 다른 토큰에 바인딩됨
- 실제 아이콘의 stroke 두께가 3-2번 표(16·20px=1.2px / 24px=1.5px / 32px~=2px)와 다름
