# Text Style 네이밍 가이드 (Figma)

`04_1Font.md`(폰트 크기/줄간격 보정 가이드)를 기반으로 확정된 폰트 크기·줄간격 값을 Figma의 **Text Styles**로 등록할 때 사용하는 네이밍 규칙이다.

## 작업 프로세스 및 보고 규칙 (모든 점검·수정 공통)

이 문서 기준으로 점검·수정 작업을 진행할 때는 항상 아래 절차를 따른다.

1. **이해** — 사용자의 요청이 정확히 무엇을 대상으로 하는지(어떤 노드·프레임·범위) 파악한다.
2. **분석** — 이 문서에 정의된 규칙과 대상의 현재 상태를 비교해 어떤 항목을 확인해야 하는지 정리한다.
3. **탐색** — `get_metadata`/`use_figma` 등으로 실제 값을 전수 조사한다. 이 단계에서 겉보기 속성(예: `strokeWeight` 숫자값)만 보지 말고, 그 속성이 실제로 적용되고 있는지(예: `strokes` 배열이 비어있지 않은지)까지 확인한다 — 적용되지 않는 leftover 값을 오류로 오인하지 않도록 주의한다.
4. **계획** — 발견한 사항을 "값 자체가 규칙과 다른 경우"와 "값은 맞는데 반영/바인딩만 빠진 경우"로 구분해 정리한다.
5. **검증** — 결론을 내리기 전에 관련 레이어를 개별로 다시 확인(스크린샷·개별 노드 조회 등)해 오탐이 없는지 재확인한다.

**오류가 발견되면 어떤 경우에도 바로 수정하지 않는다.** 발견한 내용을 먼저 표/목록으로 사용자에게 보고하고, 사용자의 확인을 받은 뒤에만 수정을 진행한다. (이 문서의 다른 절에 "값만 같으면 확인 없이 바로 바인딩 가능" 같은 예외가 있더라도, 이 규칙이 우선한다.)

## 네이밍 규칙

```
Device_Size_Weight
```

- **Device**: 스타일이 적용되는 디바이스/화면 구분자. 예: `PC`, `Tablet`, `Mobile`
- **Size**: 폰트 크기(px), `04_1Font.md` 규칙(짝수, 최소 12)으로 보정된 값을 그대로 사용
- **Weight**: 폰트 굵기 약어 (아래 표 참고)

예시: `PC_40_SB` → PC 화면, 40px, SemiBold

## Weight 약어표

| Weight (Figma style명) | 약어 |
|---|---|
| Thin | TH |
| ExtraLight | EL |
| Light | L |
| Regular | R |
| Medium | M |
| SemiBold | SB |
| Bold | B |
| ExtraBold | EB |
| Black | BL |

- 위 표에 없는 스타일명이 나오면, 이름의 대문자만 추출해 약어로 사용하고 이 표에 추가한다.
- Text Style의 **Name** 필드는 항상 이 약어를 사용한다. 단, 스타일 가이드 문서(표)의 **Weight 컬럼**에는 약어 대신 Figma 폰트 Style 풀네임(예: `SemiBold`)을 그대로 적는다. (자세한 내용은 `Document/Font_Type.md` 참고)

## 등록 절차 (Figma MCP 기준)

1. 대상 프레임의 모든 TEXT 노드를 순회하며 `(fontSize, fontWeight)` 조합을 수집해 중복 제거한다.
2. 기존 Text Styles는 전량 삭제한다 (`figma.getLocalTextStylesAsync()` → `style.remove()`).
3. 조합별로 `figma.createTextStyle()`로 새 스타일을 생성하고 이름을 `Device_Size_Weight` 형식으로 지정한다.
   - `fontName`, `fontSize`는 조합 값 그대로.
   - `lineHeight`는 `04_1Font.md` 규칙(`Math.round(fontSize*1.5/4)*4`, 단위 `PIXELS`)으로 계산한 값을 사용한다.
   - 로고로 판단된 조합은 제외한다 (`04_1Font.md` 4번 참고).
4. 스타일을 텍스트 노드에 적용할 때는 아래 순서를 따른다.
   - **반복되는 컴포넌트 인스턴스 내부의 텍스트인 경우** (여러 인스턴스가 같은 컴포넌트를 공유하는 텍스트): 개별 인스턴스마다 바인딩하지 않고, 먼저 **마스터(메인) 컴포넌트를 찾아 거기에 한 번만 바인딩**한다.
     - 인스턴스 오버라이드 노드의 id는 `I<인스턴스id>;...;<원본id>` 형식이다. 마지막 `<원본id>`로 `figma.getNodeByIdAsync(원본id)`를 호출하면 마스터 컴포넌트 안의 원본 텍스트 노드를 바로 조회할 수 있다.
     - 컴포넌트가 Variant(`COMPONENT_SET`)로 구성돼 있으면, 관련된 **모든 variant**(예: `State=On`/`State=Off` 등)의 동일 텍스트 노드에 전부 바인딩한다 — 하나만 하면 다른 상태의 인스턴스는 빠질 수 있다.
     - 마스터에 `setTextStyleIdAsync(style.id)`로 바인딩하면, 로컬 오버라이드가 없는 모든 인스턴스가 자동으로 상속받는다. 새로 추가되는 인스턴스도 별도 작업 없이 자동 적용된다.
     - 이미 개별 인스턴스에 직접 바인딩(로컬 오버라이드)이 걸려 있었다면, 마스터 바인딩 후 각 인스턴스에 `setTextStyleIdAsync("")`를 호출해 오버라이드를 해제하고 마스터 상속으로 되돌린다 (중복·불일치 방지).
   - **반복되지 않는 일반 텍스트**(인스턴스가 아니거나, 프레임마다 내용이 다르게 복제된 텍스트 등): 기존처럼 해당 노드에 직접 `node.setTextStyleIdAsync(style.id)`로 바인딩한다.
5. 검증:
   - 마스터 상속 인스턴스 텍스트는 `node.textStyleId`를 조회하면 **마스터에 바인딩된 실제 스타일 id로 정상적으로 resolve된다** (오버라이드가 없어도 빈 문자열이 아니라 마스터 값을 그대로 보여준다). 단, `setTextStyleIdAsync("")`로 로컬 오버라이드를 해제한 **직후 같은 스크립트 안에서 바로 재조회하면 일시적으로 빈 문자열("")이 보일 수 있다** — Figma가 상속 값을 재계산하는 데 약간의 지연이 있는 것으로 보이며, 오류가 아니다. 별도 호출로 다시 조회하면 정상적으로 resolve된 값이 나온다.
   - 따라서 검증은 `textStyleId`가 목표 스타일 id와 일치하는지로 확인하면 되고(직접 바인딩이든 마스터 상속이든 동일하게 적용), 방금 오버라이드를 해제한 노드는 시간을 두고 재조회해서 확인한다.
   - **인스턴스가 교체(swap)/삭제 후 재삽입되어도** 새 인스턴스가 같은 마스터 컴포넌트를 참조하면 별도 작업 없이 자동으로 올바른 스타일을 상속한다 (`I610:5174;...` 같이 인스턴스 id가 바뀐 경우로 검증됨).
   - 스타일명이 `Device_Size_Weight` 형식과 일치하는지 확인한다.

## 정렬 규칙

Figma 로컬 Text Styles 패널은 스타일이 **생성된 순서**대로 표시된다(별도의 sortPosition API 없음). 따라서 원하는 정렬을 적용하려면 기존 스타일을 전량 삭제한 뒤, 아래 순서로 다시 생성한다.

1. **Size 내림차순** (큰 폰트가 위로)
2. 동일 Size 내에서는 **Weight 내림차순**

Weight 내림차순 기준(무거운 순):

```
Black(BL) > ExtraBold(EB) > Bold(B) > SemiBold(SB) > Medium(M) > Regular(R) > Light(L) > ExtraLight(EL) > Thin(TH)
```

예시(실제 적용 결과, PC 기준 — 로고 스타일 제외 후):

```
PC_40_B
PC_32_SB
PC_20_B
PC_20_SB
PC_18_SB
PC_18_M
PC_16_SB
PC_16_M
PC_16_R
PC_14_B
PC_14_SB
PC_14_R
PC_12_B
PC_12_SB
PC_12_M
PC_12_R
```

> 스타일을 추가/변경할 때마다 이 순서를 유지하려면, 전체 스타일을 삭제 후 정렬된 순서로 재생성하고 텍스트 노드를 다시 바인딩해야 한다(스타일 id가 바뀌므로 재바인딩 필수).
>
> 단, 이건 **플러그인 API로 자동화할 때만** 해당하는 제약이다. `figma.createTextStyle()`/`getLocalTextStylesAsync()` 등 API에는 순서를 바꾸는 기능(sortPosition 등)이 없어서 삭제 후 재생성이 유일한 방법이지만, **사람이 Figma UI의 Local Styles 패널에서 직접 드래그로 순서를 옮기는 것은 가능**하다. 이 경우 스타일 id가 그대로 유지되므로 기존 바인딩이 깨지지 않고, 재바인딩도 필요 없다. 즉 정렬이 어긋난 상태를 발견하면, 삭제·재생성(자동화) 대신 **사용자가 직접 드래그로 정리**하는 방법도 있으며 이쪽이 더 간단하다.

## 오류 판정 기준

- Text Style 이름이 `Device_Size_Weight` 형식을 따르지 않음 (구분자 `_` 2개, 3개 필드)
- Size 필드가 `04_1Font.md`의 보정 규칙(짝수, 최소 12)을 따르지 않음
- 스타일에 바인딩되지 않은 텍스트 노드가 존재함 (마스터 상속 노드는 `textStyleId` 조회 시 마스터의 실제 스타일 id로 정상 resolve되므로, 이 값이 목표 스타일과 다르거나 계속 빈 문자열이면 오류)
- 반복되는 컴포넌트 인스턴스의 텍스트에 마스터 바인딩 없이 인스턴스마다 개별 로컬 오버라이드만 걸려 있음 (불필요한 중복, 4번 절차 위반)
- 동일한 `(Size, Weight)` 조합에 대해 서로 다른 이름의 스타일이 중복 존재함
- 스타일 패널 순서가 **정렬 규칙**(Size 내림차순 → 동일 Size 내 Weight 내림차순)을 따르지 않음
  - 즉, 위 항목보다 아래 항목의 Size가 더 크거나, 같은 Size 내에서 아래 항목의 Weight가 더 무거운 경우
- 로고로 판단된 텍스트에 Text Style이 등록/바인딩되어 있음
- 위에 정의되지 않은 이름 형식, 순서, 값(예: 임의의 접두사·접미사 추가, 소수점 Size, PIXELS가 아닌 lineHeight 단위 등)이 발견되는 경우 전부 오류로 간주한다.
